# MediVault combined changes

## Features included
- Patient prescription list now reads from the backend and refreshes every 5 seconds.
- Pharmacy verification history reads only audit events generated by the currently authenticated pharmacy and refreshes every 5 seconds. Verification events record the pharmacy actor. No broader medical-record access is granted.
- Password registration requires 12+ characters, lowercase, uppercase, a digit, and a special character; the registration form explains the requirements.
- Patient accounts have a stable short `patient_id` (`MV-XXXXXXXX`) separate from the internal UUID. The login response exposes `patientId`; the patient dashboard displays it.
- Medical record hash verification correctly handles the blockchain client returning a boolean and now requires local hash match plus a positive blockchain result for `valid: true`. Invalid hash strings safely fail comparison.
- Patient medical-record upload endpoint and frontend API helper have been removed. Doctor uploads remain.
- Emergency access still checks active, unrevoked grants with `expires_at > NOW()` and rejects grants beyond one hour. Consent creation now requires an explicit future expiry; existing active-consent repository queries filter expired consents.

## Apply database migrations
From `MediV/` run `npm run db:migrate`. This applies `012_add_short_patient_id.sql` and `013_generate_patient_id.sql` after earlier migrations. Back up your database first.

## Run
Backend: `npm install && npm run dev` from `MediV/`. Frontend: `npm install && npm run dev` from `MediV/frontend/`.

## Real-time behavior
This implementation uses authenticated API polling every 5 seconds rather than a persistent WebSocket. This avoids adding a new socket infrastructure dependency while providing automatic refresh. It does not push data through a socket.

## Important checks before demo
1. Verify patient prescription endpoint using a patient JWT; it must reject doctor/pharmacy tokens.
2. Verify pharmacy history with two pharmacy accounts; one account must not see the other's verification events.
3. Verify both valid and tampered medical records; `valid` should only be true when local hash and on-chain verification are both true.
4. Test consent-expired and emergency-expired API requests directly, not just the UI.
5. Password policy applies to new registrations; existing password hashes are not forcibly changed.
